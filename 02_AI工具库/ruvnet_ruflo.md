## 干什么

Ruflo 是一个"给 AI 编程助手装上团队"的平台——通俗地说，你本来用 Claude Code 写代码，它只是一个人在干活；装了 Ruflo 之后，它变成了一个能调用 100 多个专业 AI 助手（智能体）的"包工头"，需要写代码就叫 coding 智能体，需要跑测试就叫 test 智能体，需要安全检查就叫 security 智能体，它们还能互相协作、共享记忆。

它的野心很大：不是只做一个"更好用的 AI 编程工具"，而是做"AI 智能体之间的操作系统"——让不同机器、不同团队、甚至不同公司的 AI 智能体可以安全协作（叫"智能体联邦"）。比如你公司的 AI 助手需要调用另一个公司的 AI 助手的数据，Ruflo 提供了安全认证和数据脱敏的机制，让这种跨组织协作成为可能。

它原名"Claude Flow"，后来改名叫 Ruflo（"Ru"来自创建者 rUv 的名字，"flo"代表心流状态）。底层由 Cognitum.One 的智能体架构驱动，运行在基于 Rust 的高性能引擎上。对普通用户来说，最实用的部分是：它以 Claude Code 插件的形式提供，安装完就能用，不需要理解底层架构。

## 能实现什么效果

举个例子：你在做一个 Web 应用，以前用 Claude Code，你跟它说"帮我做用户登录功能"，它生成一个文件就完了，不会自动帮你跑测试、不会自动检查安全漏洞、不会自动更新文档。用了 Ruflo，它背后其实调动了好几个智能体：coding 智能体写代码，test 智能体自动生成测试用例并运行，security 智能体检查有没有常见漏洞（比如 SQL 注入），documentation 智能体自动更新文档——你只说了一句话，背后有一队 AI 在协作，最后给你的不只是代码，还有测试报告、安全检查和更新后的文档。

另一个例子：你的项目比较大，需要"持续监控代码质量"。Ruflo 有 12 个后台工作器（worker），会自动触发——比如你提交了新代码，它会自动跑审计（看看有没有明显问题）、自动检查测试覆盖率有没有掉、自动优化代码性能。相当于给你的项目配了一个"不用睡觉的 QA 团队"，每次提交代码都有一轮自动检查，能早点发现问题。

它的"智能体联邦"功能更适合团队协作：比如你的 AI 助手需要查 GitHub 的 issue、需要读数据库里的用户反馈、需要搜网上的相关资料，Ruflo 可以让这些不同来源的 AI 操作安全地进行，不会把敏感数据泄露出去。对于一个人开发来说可能用不到，但对于团队或者需要接入多个数据源的场景很有价值。

## 怎么用

- **轻量版（Claude Code 插件）**：在 Claude Code 里运行 `/plugin marketplace add ruvnet/ruflo` → 安装核心插件（`/plugin install ruflo-core@ruflo`） → 安装你想要的功能插件（比如 `ruflo-swarm` 群体协作、`ruflo-rag-memory` 记忆功能） → 之后正常使用 Claude Code，Ruflo 会在后台自动协调智能体
- **完整版（CLI 安装）**：在终端里运行一行安装命令（`curl -fsSL https://cdn.jsdelivr.net/gh/ruvnet/ruflo@main/scripts/install.sh | bash` 或者用 `npx ruflo@latest init`） → 它会往你的项目里写入配置文件和工作流 → 运行 `ruflo` 命令启动完整多智能体系统
- **网页版试用**：不想装任何东西，打开 [flo.ruv.io](https://flo.ruv.io/) → 直接用网页版聊天界面，内置了 Ruflo 的多智能体能力，还能选不同模型
- **目标规划版**：打开 [goal.ruv.io](https://goal.ruv.io/) → 用大白话输入一个目标（比如"发布包含测试和 PR 的认证重构"） → 它用 GOAP A* 规划器把目标拆解成可执行计划 → 实时看每个智能体在干什么
- **MCP 服务器接入**：如果你用其他支持 MCP 的工具，运行 `claude mcp add ruflo -- npx ruflo@latest mcp start` → 把 Ruflo 的智能体能力接入你的工具

## 运行位置

- 🖥️ **本机运行**：Windows/Mac/Linux 都支持，CLI 和插件都在本地跑
- 🌐 **网页版**：[flo.ruv.io](https://flo.ruv.io/) 和 [goal.ruv.io](https://goal.ruv.io/) 可以直接用，不用安装
- 🐋 **Docker 部署**：支持 Docker 部署，可以部署到 Cloud Run/Fly/Kubernetes
- 🔌 **集成到 Claude Code**：作为插件安装，在 Claude Code 里直接用，不需要单独运行

## 需要准备什么

- 💰 **要钱吗**：软件本身开源免费（MIT 许可证），但调用云端 AI 模型需要花钱买 API（Claude/GPT/Gemini 等）
- 🔑 **API Key**：需要至少一个 LLM 提供商的 API Key（Claude 的、OpenAI 的、或者 Google 的都行）。Ruflo 支持智能路由，可以配置多个模型，哪个可用用哪个
- 💻 **电脑配置**：对电脑本身要求不高，能跑 Node.js 就行。但如果要用本地模型（Ollama 等），需要好一点的显卡
- 📦 **要装什么**：轻量版只需要在 Claude Code 里装插件，一行命令搞定；完整版需要运行安装脚本，或者 `npx ruflo@latest init`
- 🌐 **网络**：需要能访问 AI 提供商的服务器，国内网络可能需要代理

## 配合什么软件

- **Claude Code**：最主要的使用场景，Ruflo 最初就是为 Claude Code 设计的"神经系统"
- **Codex**：也支持，OpenAI 的编程助手工具
- **MCP 客户端**：任何支持 MCP（Model Context Protocol）的工具都能接入 Ruflo 的智能体能力
- **Docker**：可以用 Docker 部署完整服务
- **独立使用**：CLI 版可以完全独立运行，不一定要配合其他工具

## 客观评价

**优点**：
- 功能非常全面，从智能体协作、记忆管理、自我学习到安全审计、后台监控，基本涵盖了"AI 编程助手升级包"的所有刚需
- 支持多 LLM 提供商，还能智能路由（哪个模型可用/便宜用哪个），灵活且成本控制友好
- 开源且 MIT 许可证，可以自己改、自己部署，不用担心厂商锁定
- 有网页版可以免安装试用，降低了体验门槛
- 100+ 个专业智能体覆盖的场景很广，不只是写代码，还包括测试、安全、文档、架构等

**缺点/坑**：
- 功能太多太复杂，新人上手需要一定学习时间，文档虽然多但不够通俗易懂
- 完整版会在你的项目里写入不少配置文件（`.claude/`、`.claude-flow/`、CLAUDE.md 等），对项目结构有侵入性
- 需要自己配置 API Key 和模型路由，对于只想"装完就用"的小白来说门槛不低
- 项目还在快速迭代中，可能会有 bug 或者破坏性更新（breaking changes）
- 信息有限：虽然功能很多，但社区相对 Claude Code 本身来说还比较小，遇到问题解决起来可能要多靠自己

**适合谁**：已经在深度使用 Claude Code 或 Codex、希望获得"智能体团队"能力的开发者；需要多人协作、或者需要接入多个数据源（GitHub/数据库/网络等）的技术团队；对 AI 智能体架构有研究兴趣的开发者。

**不适合谁**：刚接触 AI 编程工具、连 Claude Code 都还没玩明白的新手（先玩明白基础版再考虑加插件）；需求很简单、只要 AI 帮写点代码的人（用不上这么多功能，反而增加复杂度）。

**评分**：8/10 — 功能完整性和技术前瞻性都很强，但复杂度和上手门槛也高，适合有一定基础的开发者，不适合小白。

## 未来趋势

- 📈 **所处阶段**：快速成长期，star 数 5.9 万说明已经有不少人关注，但还在快速迭代中，有些功能可能还不够稳定
- 🔮 **6-12 个月走向**："AI 智能体协作"会成为编程工具的标准配置，Ruflo 在这方面的先发优势会保持；预计会进一步简化安装和使用流程，降低入门门槛；智能体联邦（跨组织协作）功能会随着 AI 在企业中的应用而变得越来越重要
- ⭐ **关注度**：4/5 — AI 智能体协作是热门方向，Ruflo 作为开源选手有较大的关注价值
