## 干什么

OpenCode 是一个"双脑"AI 编程助手——它有两个代理同时干活，一个负责"想"（Plan 代理），一个负责"干"（Build 代理）。你可以把它想象成"一个架构师 + 一个程序员"的组合，架构师先分析需求、规划方案，程序员再动手写代码。这样不容易犯大错，因为"想"和"干"是分开的。

它最厉害的地方是原生的"只读规划模式"。当你还不确定要怎么改代码的时候，切换到 Plan 代理（按 Tab 键切换），它只能读代码、不能改代码，会帮你分析项目结构、找出关键文件、规划改动方案。等你满意了，再切换到 Build 代理，它才有改代码的权限。相当于"先让军师出主意，再让士兵执行"，安全系数高。

它是开源项目（AGPL 许可证），不是某家大公司的产品，更新快、社区活跃。支持几乎所有主流大模型，也能用本地模型（通过 Ollama）。除了终端版，还有桌面应用版（目前是 Beta 阶段），可以选择用命令行还是图形界面。

## 能实现什么效果

举个例子：你有一个运行了好几年的电商网站项目，现在要加一个"会员积分"功能，涉及用户表、订单表、积分记录表、前端页面、后端 API，改动点多、容易漏。以前你要自己画 ER 图、列改动清单、逐个文件改，可能要花两三天。用 OpenCode，你按 Tab 切换到 Plan 代理，跟它说"我要加会员积分功能，用户下单后获得积分、积分可以抵扣现金，帮我规划需要改哪些文件、加哪些表"——它会读整个项目，给出详细规划：需要加一张积分记录表、需要改用户表和订单表的结构、需要在后端加三个 API、前端要加两个页面。你确认规划没问题，再切换到 Build 代理让它执行。原本两三天的事，可能大半天就搞定了。

另一个例子：你接手了一个别人的项目，代码写得很烂，但没有测试、没有文档，你完全不敢动。用 OpenCode 的 Plan 代理（只读模式），让它"分析这个项目，找出最急需重构的三个模块，并给出重构方案"——它会读所有代码，指出哪些函数太复杂、哪些模块耦合太紧、哪些地方有潜在 bug，并给出重构的优先级和建议。相当于身边有个资深架构师帮你做代码审查和技术债梳理。

它还能配合"子代理"（Subagent）处理复杂任务。比如你说"帮我研究一下怎么把项目从 Vue 2 升级到 Vue 3，需要考虑兼容性"，它会调用 `@general` 子代理，这个子代理专门处理复杂搜索和多步骤任务，会查官方文档、看迁移指南、列出所有需要改的地方、甚至给你写一份迁移方案文档。

## 怎么用

- **规划阶段（先用 Plan 代理）**：打开终端进入项目 → 运行 `opencode` → 按 Tab 切换到 Plan 代理 → 说"我想加一个评论功能，帮我校划需要改什么" → 它只分析不改动 → 给你详细方案 ✓
- **执行阶段（再用 Build 代理）**：确认规划没问题 → 按 Tab 切换到 Build 代理 → 说"按照刚才的规划开始实现" → 它开始改代码 → 每次改动都展示 diff → 你确认后继续
- **快速改代码（直接用 Build 代理）**：运行 `opencode` → 说"把所有硬编码的 API 地址改成从环境变量读取" → 它扫描整个项目 → 改代码 → 展示 diff → 确认后保存
- **复杂研究任务（用子代理）**：运行 `opencode` → 说"@general 帮我研究一下这个项目用的框架的最新版本有什么新特性，要不要升级" → 子代理会联网查文档、对比版本差异、给出建议
- **桌面应用版**：安装桌面应用（从 releases 页面下载）→ 打开应用 → 和终端版一样的操作，但有图形界面，更直观

## 运行位置

- 🖥️ **Windows / Mac / Linux 都可以**：有终端 CLI 版和桌面应用版（Beta）
- 需要联网（调用云端 AI 模型），也支持本地模型（Ollama）离线运行
- 终端 CLI 版：在终端里运行，适合熟悉命令行的用户
- 桌面应用版：有图形界面，Mac/Windows/Linux 都有，适合不喜欢命令行的用户
- 未来可能会出 VS Code 插件（社区在讨论）

## 需要准备什么

- 💰 **要钱吗**：OpenCode 本身是开源免费的。但用哪个 AI 模型就付哪个的钱。如果用 Anthropic 的 Claude，需要付 API 费用（按量计费）。如果用本地模型（Ollama），完全不用钱，但需要好点的显卡
- 🔑 **API Key**：根据你选的模型，需要对应的 API Key。可以在 OpenCode 的交互界面里配置，支持多个 Key 同时配置（比如同时配 Claude 和 GPT-4，随时切换）。也可以设置 `OPENCODE_API_KEY` 环境变量用 OpenCode 官方的托管模型服务（付费）
- 💻 **电脑配置**：要求不高，普通办公电脑就能跑 CLI。如果要跑本地模型，需要好点的显卡（8GB 显存起步）
- 📦 **要装什么**：
  - 一键安装（推荐）：`curl -fsSL https://opencode.ai/install | bash`
  - npm：`npm i -g opencode-ai@latest`
  - Homebrew（Mac/Linux）：`brew install anomalyco/tap/opencode`
  - Windows（Scoop）：`scoop install opencode`
  - Windows（Chocolatey）：`choco install opencode`
  - 桌面应用：从 [Releases 页面](https://github.com/anomalyco/opencode/releases) 下载安装包
- 🌐 **网络**：用云端模型需要能访问对应的 API 服务器。用本地模型（Ollama）完全不需要联网

## 配合什么软件

- **终端**：CLI 版需要配合终端使用
- **Git**：强烈建议项目用 Git 管理（OpenCode 改代码前会自动创建 checkpoint，改错了可以回退）
- **Ollama**：如果用本地模型，需要先安装 Ollama 并下载模型
- **桌面应用**：可以独立使用，不依赖终端
- **文档工具**：支持读取 GEMINI.md（类似 Claude 的 CLAUDE.md）作为项目上下文文件，可以配合 Markdown 文档使用

## 客观评价

**优点**：
- 双代理模式（Plan + Build）是独门绝技，先规划再执行，不容易犯大错
- 开源免费（AGPL 许可证），社区活跃，更新快
- 模型无关，支持几乎所有主流大模型，也能用本地模型
- 有桌面应用版（Beta），不熟悉命令行的用户也能用
- 子代理系统适合处理复杂研究和多步骤任务
- 按 Tab 切换代理的设计很直观，用起来顺手

**缺点/坑**：
- AGPL 许可证比较严格，如果用在商业项目里需要注意合规问题（不如 Apache 2.0 那么自由）
- 桌面应用还在 Beta 阶段，可能有 bug
- 需要自己准备 API Key（或本地模型），对于完全新手来说配置有点麻烦
- 双代理模式虽然安全，但也意味着"要多操作一步"（切换代理），有时候会觉得麻烦
- 社区和生态还不如 Claude Code 和 Cline 那么成熟
- 国内网络访问 Anthropic/OpenAI 的 API 可能需要代理

**适合谁**：有一定编程经验、希望"先规划再执行"更安全的开发者。特别适合接手老项目、做大规模重构的场景。

**不适合谁**：完全零基础想"不写代码做网站"的人、希望"一键搞定不用操心"的人（双代理模式需要你参与规划）。

**评分**：8/10 — 双代理模式很有价值，但许可证和成熟度稍逊于头部竞品

## 未来趋势

- 📈 **所处阶段**：快速增长期。开源社区很活跃，stars 数增长很快
- 🔮 **6-12 个月走向**：桌面应用会从 Beta 毕业（变成正式版），可能会出 VS Code 插件，子代理系统会更强大（可能支持自定义子代理）。本地模型的支持也会越来越好
- ⭐ **关注度**：4/5 — 有特色的双代理模式，值得关注，但生态还在建设中
