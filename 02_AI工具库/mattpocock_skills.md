# Matt Pocock Skills — 真正的工程师怎么用 AI 写代码

> ⭐ 137,784 | 📅 2026-06-20 | [GitHub](https://github.com/mattpocock/skills)
>
> 💡 **怎么标记**：改上面 `interest` 数字 → 3=必装 2=想试 1=观望 0=跳过 → 改完按 Ctrl+S 保存

## 干什么

这是 TypeScript 大神 Matt Pocock 每天在用的一套 AI 编程"武功秘籍"。和别的技能包不同的是，它不是给你一堆花里胡哨的提示词模板，而是解决了 AI 编程中四个根本性问题。

问题一：AI 不知道你到底想要什么。解决方案是 `/grill-me`——让 AI 像审讯一样反复追问你，直到它完全搞懂你的需求再开工。问题二：AI 话太多、太啰嗦。解决方案是建立一套"共享语言"（项目中的人和 AI 统一用词），让沟通高效精准。问题三：AI 写的代码跑不起来。解决方案是 `/tdd`（测试驱动开发）——让 AI 先写测试再写代码，写通过的才算数。问题四：AI 写的代码越堆越乱。解决方案是定期让 AI 审查代码架构，该重构就重构。

简单说：如果你觉得 AI 写代码"能用但不好用"、"越写越乱"、"改需求就崩"，这套技能就是专门治这些病的。

## 能实现什么效果

最直接的效果：让 AI 从"能写代码的实习生"升级为"靠谱的高级工程师"。装了这套技能后，AI 会在动手之前先跟你确认需求细节（避免理解偏差），写代码时先写测试（保证代码真的能用），修完 bug 后还会写回归测试（避免下次再犯）。

具体到量化：使用了 TDD 技能后，AI 写出的代码首次可用率大幅提升（因为被测试兜底了）；使用了"共享语言"后，AI 的废话显著减少，token 消耗降低 20-30%；定期用架构审查技能，可以避免代码慢慢烂成一坨。

## 怎么用

- **30 秒装好**：`npx skills@latest add mattpocock/skills` → 选你用的 AI 工具 → 选你要的技能（选 `/setup-matt-pocock-skills` 走配置向导）→ 搞定。
- **开工前用 `/grill-me`**：每次要写新功能时，先用这个命令让 AI 追着你问细节，直到你们对需求理解完全一致。
- **写代码用 `/tdd`**：进入"测试驱动开发"模式，AI 先写失败的测试 → 再写代码让测试通过 → 最后重构优化。
- **遇到 bug 用 `/diagnosing-bugs`**：AI 会系统性地排查问题：复现 bug → 缩小范围 → 提出假设 → 打日志验证 → 修复 → 写测试防止复发。
- **代码越来越乱用 `/improve-codebase-architecture`**：AI 扫描整个项目，生成可视化报告告诉你哪里需要重构，然后你选一个方向让它重构。

## 运行位置

- 本地电脑（macOS / Linux，Windows 理论上也能用）
- 作为 AI 编程工具的插件运行，不需要额外服务器

- 免费开源（MIT 协议）
- 需要一个支持的 AI 编程工具（Claude Code、Codex、Cursor、Gemini CLI、OpenCode 等）
- 不需要额外的 API Key 或注册
- 需要 Git 来克隆/安装
- 电脑配置：普通笔记本就行

## 配合什么软件

- 必须配合 AI 编程工具使用（推荐 Claude Code 或 Cursor）
- 工程类技能需要配合 GitHub / Linear（任选其一作为 Issue 跟踪器）
- 独立使用，不需要装别的

## 客观评价

**优点**：思路极其务实——不是花哨的 AI 技巧，而是把几十年软件工程经验翻译成了 AI 能执行的流程；Matt Pocock 本人就是 TypeScript 圈的顶级专家，技能质量有保障；安装简单到离谱（一条命令）；社区极活跃（13 万+ star），持续更新。

**缺点**：技能偏专业开发者视角，对完全不懂编程的人不友好；部分技能依赖特定的项目管理工具（GitHub/Linear）；文档全是英文，中文用户理解门槛较高；某些场景下 AI 执行这些流程会比较慢（尤其是 TDD 和架构审查）。

**适合谁**：有一定编程基础的开发者、想要用 AI 做严肃项目（不是玩具）的人。**不适合**：完全不懂编程的初学者、只是想让 AI 帮忙写个简单脚本的人。

**评分 9/10**：目前最务实的 AI 编程技能包，没有之一。扣 1 分是因为对非专业开发者不够友好。
