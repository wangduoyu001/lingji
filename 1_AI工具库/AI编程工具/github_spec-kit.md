# Spec Kit

> ⭐ 114,280 | 📅 2026-06-20 | [GitHub](https://github.com/github/spec-kit)
>
> 💡 **怎么标记**：改上面 `interest` 数字 → 3=必装 2=想试 1=观望 0=跳过 → 改完按 Ctrl+S 保存

## 干什么

Spec Kit 是 GitHub 官方出品的"AI 编程导航仪"。传统让 AI 写代码的痛点是什么？你说"帮我做个相册管理 App"，AI 直接就开始写代码了，写了一半你发现它理解错了你的意思，或者代码结构一团乱。Spec Kit 的做法是：先别急着写代码，咱们先把"你要做什么"聊清楚，写成一份规格说明书，然后 AI 按照这份说明书一步步来。

打个比方：传统开发像让装修工人直接进场砸墙，结果砸完了你才发现他要装的是欧式风格而你想要的是日式。Spec Kit 的做法是先出设计图纸（规格书），确认了再动工，每一步都有检查点。

它提供 7 个斜杠命令（`/speckit.specify`、`/speckit.plan`、`/speckit.tasks` 等），覆盖从"我要做什么"到"代码写完上线"的整个流程。支持 30+ 种 AI 编程工具（包括 Claude Code、Codex、Cursor、Gemini CLI 等）。

## 能实现什么效果

用了 Spec Kit 之后，你从一个"给 AI 下模糊指令然后反复修改"的人，变成了一个"定义规则然后验收成果"的监工。AI 不再凭感觉写代码，而是严格按照你确认过的规格来执行。

实际效果：一个全栈 Web 应用，从说"我想做个什么东西"到代码完整可运行，按照 Spec Kit 的流程走下来，返工次数减少 50% 以上。因为每一步都有明确的验收标准，你不会在最后才发现"这不对"。

最终产出：完整的项目代码（含测试）、规格说明书、技术实现计划、拆分好的任务列表，甚至可以自动转为 GitHub Issues。等于不只是代码写完了，项目管理文档也一块儿有了。

## 怎么用

- **从零开始一个新项目**：`specify init my-app` 初始化 → `/speckit.constitution` 设定项目原则（比如"所有 API 必须有测试"）→ `/speckit.specify` 描述你要做什么 → `/speckit.plan` 确定技术方案 → `/speckit.tasks` 自动拆分任务 → `/speckit.implement` 一键执行所有任务。
- **给现有项目加新功能**：在已有项目里直接 `/speckit.specify` 描述新需求 → 后续流程同上，AI 会自动处理新旧代码的兼容。
- **探索多个方案**：不确定用 React 还是 Vue？让 Spec Kit 并行生成两个方案的技术计划，对比后再决定。
- **质量检查**：代码写完后用 `/speckit.checklist` 自动生成检查清单，逐项验证代码质量。
- **转成 GitHub Issues**：`/speckit.taskstoissues` 一键把任务列表变成 GitHub Issues，方便团队协作。

## 运行位置

- **本地电脑**：Windows / macOS / Linux 都能用
- 本质是命令行工具 + AI 编程工具的组合，在你的电脑上跑

## 需要准备什么

- 完全免费开源（MIT 协议）
- 不需要额外注册 Spec Kit 账号
- 需要 Python 3.11+
- 需要安装至少一个 AI 编程工具（Claude Code、Codex、Cursor、Gemini CLI 等任一即可）
- 安装命令：`uv tool install specify-cli --from git+https://github.com/github/spec-kit.git`
- 电脑配置：普通笔记本就行，不需要独显（AI 推理在云端）

## 配合什么软件

- **必须配合 AI 编程工具使用**：Claude Code（推荐）、Codex CLI、Cursor、Gemini CLI 等 30+ 种
- 和 Git 配合：所有规格文件自动纳入版本管理
- 和 GitHub Issues 配合：可一键把任务导出为 Issues

## 客观评价

**优点**：从根本上解决了 AI 写代码"理解偏差"的问题，思路非常正确；GitHub 官方出品，维护有保障，30+ 工具支持覆盖面广；7 步标准化流程让新手也能写出结构良好的代码；自动生成规格书、计划、任务列表，项目管理文档不用手写。

**缺点**：学习成本——你得先理解"规格驱动开发"是什么，不是上来就能用；对于非常简单的小需求（改个字、修个 bug），这套流程就显得太繁琐了；目前主要靠英文学术词汇（constitution、specify、converge），中文用户理解起来有点费劲；对 AI 编程工具的依赖度高，工具本身不好用整个流程都难受。

**适合谁**：经常用 AI 写代码但总是被 AI 气到的开发者、想做严肃项目（不是玩具项目）的个人开发者、小型团队希望建立标准化开发流程。**不适合**：只想让 AI 帮忙改一行代码的场景、没有任何编程基础的小白。

**评分 8/10**：理念极好，执行到位。扣分是因为入门曲线偏陡、简单场景下过度工程化。
