## 干什么

Pi 是一个"AI 编程助手工具集"——它把几个常用功能打包在一起：一个能统一调用各种大模型（OpenAI/Claude/Google 等）的接口、一个能运行 AI 代理（Agent）的运行时、以及一个可以在终端里直接用的编程助手。通俗地说，它就像是"给 Claude Code 加了多模型切换能力"——你不用只绑定一家 AI，可以在不同模型之间灵活切换，哪个好用用哪个。

它的核心设计是"模块化"的：你想只用它的多模型接口（pi-ai），可以单独用；你想搭自己的 AI 代理，可以用它的代理运行时（pi-agent-core）；你想直接在终端里让 AI 帮你写代码，可以用它的编程助手（pi-coding-agent）。这种"想用哪个用哪个"的设计，比那些大而全但不灵活的工具更实用。

它还有一个 Terminal UI（终端界面），不是纯黑底白字的命令行，而是有按钮、有进度条、有彩色显示的"半图形界面"，在终端里用也不会觉得枯燥。而且它支持把自己运行的会话数据分享出来（发到 Hugging Face），帮助改进 AI 编程助手的能力——如果你关心 AI 发展，用它的同时也在为行业做贡献。

## 能实现什么效果

举个例子：你在写一个项目，有时候用 Claude 写代码效果好，有时候用 GPT 理解复杂逻辑更厉害，有时候用 Google Gemini 处理多模态（图文混合）更方便。以前你要分别开三个网站、三个工具，切来切去很麻烦。用了 Pi，你在一个工具里就能切换这三个模型，同个终端界面、同个操作方式，不用反复适应新工具。原来要在三个工具之间来回倒腾的事，现在一个工具全搞定。

另一个例子：你在做一个需要 AI 代理（Agent）功能的应用——比如"让用户用大白话描述需求，AI 自动拆解成多个步骤然后执行"。Pi 的代理运行时（pi-agent-core）已经把"工具调用"、"状态管理"这些底层活都干好了，你只需要关心你的业务逻辑（比如"这个代理能调用哪些工具"、"怎么判断任务完成了"），不用自己从零写一套代理运行框架。相当于你要把一块地建成小区，Pi 已经把"三通一平"（水电气路）都搞定了，你直接盖楼就行。

它的编程助手（pi-coding-agent）还能"自己夸自己"——它运行的过程中的数据可以匿名分享到 Hugging Face，帮助研究者更好地理解 AI 编程助手在真实场景下怎么工作、哪里容易出错、怎么改进。如果你愿意分享数据，相当于在用它的同时也在推动整个行业进步。

## 怎么用

- **当多模型接口用**：在你的代码里引入 `@earendil-works/pi-ai` → 配置好你想用的几个模型（OpenAI/Claude/Google） → 调用统一接口，让 AI 干活 → 哪个模型效果好自动切换或手动切换
- **当代理运行时用**：引入 `@earendil-works/pi-agent-core` → 定义你的代理能调用哪些工具（比如"搜索网页"、"读文件"、"运行代码"） → 定义任务完成条件 → 启动代理，让它自动循环执行直到任务完成
- **当终端编程助手用**：安装 `@earendil-works/pi-coding-agent` → 打开终端，运行 `pi` → 用大白话描述你想让代码做什么 → 它生成代码、让你确认 → 改完自动提交 Git（如果你配了 Git 集成）
- **切换模型**：在配置文件里改一行 → 从 Claude 换成 GPT、或者换成 Google Gemini → 同个界面，不同模型后端
- **分享会话数据**：运行完后选择分享 → 数据上传到 Hugging Face → 帮助 AI 研究社区改进编程助手

## 运行位置

- 🖥️ **本机运行**：Windows/Mac/Linux 都支持（它是 TypeScript/Node.js 写的，跨平台）
- 🔌 **终端使用**：在终端（命令行）里运行，有 TUI（半图形界面），比纯文字命令行好看和好用
- ☁️ **可嵌入别的工具**：它的各个包（pi-ai/pi-agent-core 等）可以当作普通 npm 包引入你自己的项目

## 需要准备什么

- 💰 **要钱吗**：软件本身开源免费（MIT 许可证），但调用云端 AI 模型需要花钱买 API（OpenAI/Claude/Google 都要）
- 🔑 **API Key**：至少需要一个 AI 模型提供商的 API Key（OpenAI 的、Claude 的、或者 Google 的都行，看你想用哪个）。如果你多个都想试，就多个都配上
- 💻 **电脑配置**：能跑 Node.js 的电脑都行，对配置要求不高
- 📦 **要装什么**：需要先装 Node.js 18 以上版本，然后用 `npm install` 装依赖。如果想用编程助手（pi-coding-agent），需要全局安装：`npm install -g @earendil-works/pi-coding-agent`
- 🌐 **网络**：需要能访问 AI 提供商的服务器（OpenAI/Claude/Google 等），国内网络可能需要代理

## 配合什么软件

- **终端**：必须在终端里运行（Windows 的 PowerShell/CMD、Mac 的 Terminal 等）
- **Git**：它支持跟 Git 集成，代码改完自动提交，建议项目用 Git 管理
- **VS Code**：可以在 VS Code 的终端里用，不用切窗口
- **Hugging Face**：可选，如果想分享会话数据帮助研究，需要有个 Hugging Face 账号
- **独立使用**：它的各个包也可以单独引入你自己的 Node.js 项目，不一定非要当命令行工具用

## 客观评价

**优点**：
- 多模型支持做得好，不用被一家 AI 绑定，哪个好用切哪个，灵活
- 模块化设计，想用哪个功能拿哪个，不需要全盘接收，适合不同需求的人
- 有 TUI 界面，终端工具也能做得好看和好用，不是纯黑底白字的"劝退风"
- 开源且 MIT 许可证，可以随便改、随便用，包括用在商业项目里
- 支持分享会话数据给研究社区，有公益价值

**缺点/坑**：
- 需要自己配置 API Key，而且如果要用好几个模型就要配好几套 Key，对新手有一定门槛
- 文档虽然有不少，但作为"工具集"，不同包之间怎么配合用，文档写得不够清楚，可能需要自己摸索
- 网络要求高，要能访问多个 AI 提供商的服务器，国内用户可能需要折腾代理
- 它不是一个"开箱即用"的工具，更需要你是开发者、能写代码去集成，而不是"安装完就能给小白用"
- 跟 Claude Code、Cursor 等更成熟的 AI 编程工具比，生态和社区还相对小

**适合谁**：已经在用多个 AI 模型、希望在同一个工具里统一管理的开发者；想自己搭 AI 代理（Agent）应用、需要一套好用的底层框架的开发者；对 AI 编程助手有研究兴趣、愿意分享数据帮助改进的人。

**不适合谁**：完全不懂编程、只想装个工具帮自己写代码的小白（这个工具更需要你会写代码去用它，而不是它帮你写代码）；只想用一家 AI 就够了、不需要多模型切换的人（用 Claude Code 就够了，不需要它）。

**评分**：7/10 — 多模型统一接口和模块化设计是亮点，但配置门槛和文档完善度还有提升空间，适合有一定基础的开发者。
