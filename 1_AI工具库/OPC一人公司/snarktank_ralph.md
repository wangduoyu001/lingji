## 干什么

Ralph 是一个"让 AI 编程助手自动循环干活"的工具——通俗地说，就是你把任务清单（PRD，产品需求文档）写好，它自动一遍遍叫 AI（比如 Claude Code 或 Amp）出来干活，干完一个任务再干下一个，直到全部做完为止。你可以把它想象成"一个不用休息的项目经理"——它不停地把任务分配给 AI，检查干得对不对，对了就记录下来继续下一个，直到所有任务都完成。

它的核心设计理念是：每次叫出来的 AI 都是"全新的一轮"（干净的上下文），不会把上一轮的信息带进来造成混乱。那 AI 怎么记住之前干了什么呢？靠三个东西：Git 提交记录（之前改了哪些文件）、progress.txt（记录每次的收获和坑）、prd.json（记录哪些任务已经完成、哪些还没）。这就像人换班的时候看交接文档——新来的不知道之前发生了啥，但看了记录就知道从哪接着干。

这个项目基于 Geoffrey Huntley 提出的"Ralph 模式"，在 AI 编程圈子里小有名气。它的适用场景是：你有一个功能清单要开发，不想一直坐在电脑前盯着 AI 干活，而是希望它能自己循环做、做完了通知你。

## 能实现什么效果

举个例子：你要开发一个"用户登录注册"模块，里面拆出了 8 个小任务（设计数据库表、写注册接口、写登录接口、加密码加密、写前端表单、加输入验证、接入 Session、写测试）。以前你要一个个盯着 AI 做，或者自己一个个写。用了 Ralph，你先把这 8 个任务写成 PRD（产品需求文档），然后运行 Ralph，它自动开始：先让 AI 做第一个任务（设计数据库表），AI 做完了自动运行类型检查、跑测试，都通过了就提交代码、在 prd.json 里标记"已完成"，然后自动开始第二个任务……你可以去干别的，过一会儿回来看，8 个任务可能已经自动做完了。

另一个例子：你在做一个个人项目，希望每天下班前把当天的任务清单丢给 Ralph，让它晚上自己跑，第二天早上来看进度。因为它每次都是"全新的一轮"AI，不会出现"上下文太长、AI 开始胡说"的问题，每个任务都是独立完成的，质量更有保障。而且它每次干完都会把"学到了什么"写到 progress.txt，后面的任务可以借鉴前面的经验，越跑越顺。

它还能跟你用的 AI 编程工具深度集成。比如你用 Claude Code，Ralph 可以直接调用 Claude Code 来干活；你用 Amp（另一个 AI 编程工具），它也支持。甚至可以作为 Claude Code 的插件安装，在 Claude Code 里直接用 `/ralph` 命令启动自动循环。

## 怎么用

- **写任务清单**：先跟 AI 说"帮我写一个 PRD（产品需求文档），功能是 XXX" → AI 帮你生成一个 markdown 格式的 PRD → 保存到项目里的 `tasks/` 文件夹
- **转成 Ralph 格式**：跟 AI 说"把这个 PRD 转成 Ralph 的 prd.json 格式" → 生成一个 `prd.json` 文件（里面每个任务有编号、优先级、完成状态）
- **启动自动循环**：在终端里运行 `./scripts/ralph/ralph.sh` → Ralph 开始自动循环：挑一个未完成的任务 → 叫 AI 出来干活 → 检查质量 → 提交代码 → 更新状态 → 下一个任务
- **作为 Claude Code 插件用**：在 Claude Code 里运行 `/plugin marketplace add snarktank/ralph` → 安装完直接用 `/prd` 生成需求、用 `/ralph` 启动自动循环，不用手动拷贝文件
- **查看进度**：随时打开 `prd.json` 看哪些任务完成了、哪些还没；打开 `progress.txt` 看 AI 每次学到了什么

## 运行位置

- 🖥️ **本机运行**：Windows/Mac/Linux 都支持（Ralph 本身是一个 bash 脚本，Windows 用户需要用 Git Bash 或 WSL）
- 🔌 **集成到 AI 工具**：可以作为 Claude Code 的插件运行，也可以在终端里独立运行
- 📝 **需要 Git 仓库**：你的项目必须是一个 Git 仓库（因为 Ralph 靠 Git 提交记录来保持"记忆"）

## 需要准备什么

- 💰 **要钱吗**：Ralph 本身是开源免费的，但需要你有 AI 编程工具的访问权限（下面详细说明）
- 🔑 **AI 工具**：需要安装并配置好以下其中一个：Amp CLI（默认）或者 Claude Code（`npm install -g @anthropic-ai/claude-code`）。这些工具本身可能需要 API Key 或者订阅
- 💻 **电脑配置**：能跑 AI 编程工具的电脑都行，对配置要求不高
- 📦 **要装什么**：需要安装 `jq`（一个处理 JSON 的命令行工具，Mac 上用 `brew install jq`）；需要把 `ralph.sh` 脚本拷贝到你的项目里
- 🌐 **网络**：需要能访问 AI 编程工具的服务器（Claude Code 需要连 Anthropic 的服务器，国内可能需要代理）

## 配合什么软件

- **Claude Code**：Ralph 默认支持调用 Claude Code 来干活，也可以作为 Claude Code 的插件安装
- **Amp**：另一个 AI 编程工具，是 Ralph 的默认后端
- **Git**：必须使用，Ralph 靠 Git 提交记录来保持任务之间的"记忆"
- **终端**：需要在终端（命令行）里启动和管理 Ralph
- **文本编辑器**：用来查看和编辑 `prd.json`、`progress.txt` 等文件

## 客观评价

**优点**：
- 自动化程度高，适合"丢任务、去干别的、回来看结果"的工作方式，提升效率
- 每次 AI 都是干净上下文，不会出现"上下文太长导致质量下降"的问题
- 用 Git + 文本文件保持记忆，简单可靠，不会丢信息
- 支持多种 AI 编程工具（Claude Code/Amp），灵活
- 开源，可以自己改逻辑（比如加自定义的质量检查步骤）

**缺点/坑**：
- 需要你会写 PRD（产品需求文档），如果任务拆得不好（太大或模糊），AI 可能做不出来或者做得很差
- 每个任务应该是"一口能吃完"的大小（能在一次 AI 上下文窗口里完成），太大的任务需要你事先拆细，增加了使用前的工作量
- bash 脚本在 Windows 上需要用 Git Bash 或 WSL，对纯 Windows 用户不太友好
- AI 自动提交代码，虽然会跑质量检查，但偶尔还是会提交有问题的代码，需要人工定期复查
- 项目还比较新，可能会遇到 bug 或者跟你的特定项目结构不兼容的情况

**适合谁**：已经在用 Claude Code 或 Amp 等 AI 编程工具、希望进一步提升自动化程度的开发者；有多个小任务要做、希望 AI 能自动循环完成的人；对 bash 脚本和 Git 工作流比较熟悉的人。

**不适合谁**：不会写 PRD、不知道怎么把大功能拆成小任务的人；项目还没用 Git 管理的人；纯 Windows 用户且不想装 WSL 的人。

**评分**：7/10 — 自动化思路很好，但对使用者的任务拆分能力和 Git 熟悉度有一定要求，入门门槛不低。
