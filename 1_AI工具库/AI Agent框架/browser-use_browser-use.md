## 干什么

Browser Use 是一个让 AI 能像人一样操作浏览器的工具。你给它一个任务（比如"去 GitHub 上找 browser-use 这个仓库，告诉我有多少 star"），它会自己打开浏览器、导航到网页、读取页面内容、点击按钮、填写表单，最后把结果告诉你。你可以把它理解成"一个会操作浏览器的 AI 员工"——你不用自己写爬虫代码，直接用大白话告诉它要干什么就行。

它最新的 v0.13 版本把核心用 Rust 重写了，速度比以前快很多，而且更稳定。Rust 是一种系统级编程语言，以高性能和内存安全著称，用它重写核心意味着这个工具现在能处理更复杂的任务而不容易崩溃。

它既能当 Python 库用在代码里，也有命令行工具（CLI）可以直接在终端里用，还能作为 Claude Code 等 AI 编程工具的插件来用。简单说就是：你想让 AI 帮你自动化任何浏览器操作，这个工具都能搞定。

## 能实现什么效果

举个例子：你要每天手动去好几个网站查价格、填表、下载报表，每次要花 1 小时。用 Browser Use，你写一段简单的 Python 代码（或者直接用命令行），告诉它"每天上午 9 点，去这几个网站把价格抄下来，整理成表格发我邮箱"——设好之后，之后每天它自动帮你干，你只需要看结果。省下的时间可能是每天 1 小时，一年就是 365 小时。

另一个例子：你在做电商，需要批量查看竞品的详情页、提取关键信息（价格、销量、评价）。以前要雇人一个个复制粘贴，或者自己写爬虫（容易被封）。用 Browser Use，你告诉它"打开这 100 个商品链接，把价格和评价数记下来"，它自动帮你操作浏览器逐个访问、提取信息、整理成表格。速度快、不容易被封（因为它真的在"用浏览器"而不是发爬虫请求）。

它还能帮你做**网页自动化测试**——比如你做了一个网站，改了代码后想检查所有按钮是不是还能点、表单能不能提交。让 Browser Use 自动帮你跑一遍，比手动测试快 10 倍，而且不会漏掉某个页面。

## 怎么用

- **想快速试试（命令行）**：`pip install "browser-use[core]"` 安装 → 运行 `browser` 命令进入终端界面 → 输入任务（比如 `open https://github.com`）→ 看它操作浏览器
- **想在代码里用（Python）**：安装后 `from browser_use.beta import Agent, ChatBrowserUse` → 写几行代码指定任务和模型 → 运行，AI 自动操作浏览器
- **想当 Claude Code 的插件用**：按文档把 SKILL.md 放到 Claude Code 的 skills 目录 → 之后在 Claude Code 里就能直接让它"帮我用浏览器查 XX"
- **想不用自己装（云版）**：去 [Browser Use Cloud](https://cloud.browser-use.com) 注册 → 直接用云端浏览器，自带反检测和代理轮换，不用自己搞定这些技术问题
- **想做复杂自动化流程**：用它的自定义工具（Tools）功能，给代理加上专属工具（比如"发邮件""存数据库"）→ 代理在操作浏览器的过程中可以调用这些工具，实现更复杂的自动化

## 运行位置

- 🖥️ **本机**：Windows、Mac、Linux 都可以，需要 Python 3.11+。装完之后会在本机启动一个浏览器（默认 Chrome/Chromium）来操作
- ☁️ **云端**：可以用 [Browser Use Cloud](https://cloud.browser-use.com) 的托管版，不用自己装，浏览器在云端跑，自带反检测和代理轮换
- 🐳 **服务器**：可以部署到服务器上跑定时任务，适合需要持续运行的场景（比如每天自动爬数据）
- 🔌 **远程浏览器**：支持连接远程浏览器（通过 CDP 协议），这样可以在本机写代码、但浏览器在云端跑，适合需要高 stealth（反检测）的场景

## 需要准备什么

- 💰 **要钱吗**：开源版免费（MIT 许可证）。云版按使用量付费，但有免费额度。如果自己部署，只需要付 API 调用费和大模型费用
- 🔑 **API Key**：需要一个大模型的 API Key。推荐用它们自家的 `ChatBrowserUse`（专门为浏览器自动化优化的模型，速度快、准确率高），也支持 OpenAI、Anthropic、Google 的模型。如果用的模型需要 API Key，就把 Key 写到 `.env` 文件里
- 💻 **电脑配置**：要求不高，能跑 Python 和普通浏览器的电脑都行。如果要用云版，普通电脑能上网就行
- 📦 **要装什么**：Python 3.11+、pip 或 uv（推荐用 uv，更快）。安装命令：`pip install "browser-use[core]"` 或 `uv add "browser-use[core]"`。`[core]` 会额外安装 Rust 核心运行时
- 🌐 **网络**：需要能访问要操作的网站。如果要操作的网站在国外，可能需要代理。云版自带代理轮换，不用自己搞定

## 配合什么软件

- **Python**：主要用 Python 调用，也可以完全用命令行不用写代码
- **Claude Code / Cursor**：可以当这些 AI 编程工具的插件（Skill）来用，让编程 AI 具备操作浏览器的能力
- **Docker**：可以用 Docker 跑隔离的浏览器环境，更安全
- **Browser Use Cloud**：推荐配合它的云服务来跑浏览器，有反检测、代理轮换、验证码解决，比自己搞靠谱
- **独立使用**：不依赖其他软件，装完 Python 包就能用

## 客观评价

**优点**：
- v0.13 用 Rust 重写核心后，性能和稳定性大幅提升，是目前同类工具里最快的之一
- 支持反检测（不容易被网站识别为机器人）、代理轮换（换 IP）、验证码解决（云版），适合严肃的自动化任务
- 有云版，不想自己折腾可以直接用托管版，省心
- 支持自定义工具，可以扩展代理的能力（不只是操作浏览器，还能调 API、存数据库等）
- 有 CLI（命令行工具），可以快速测试，不用写代码
- Benchmark 公开（[browser-use/benchmark](https://github.com/browser-use/benchmark)），性能透明，不是在吹牛

**缺点/坑**：
- 需要大模型 API，每操作一次都要调用 API，频繁使用的话费用可能不低（虽然它们自家的模型已经优化了成本）
- 网站结构一变（比如改版了），代理可能就操作不了了，需要更新任务描述或代码
- 反检测不是万能的，有些网站（尤其是有强验证码的）还是可能挡住
- 开源版需要自己搞定浏览器环境，Windows 上可能遇到兼容性问题
- 学习曲线：虽然号称简单，但要真正用起来还是需要懂一点 Python 和基本的 AI 概念

**适合谁**：需要做网页自动化的人（数据分析师、电商运营、测试工程师）、想做 AI 代理的开发者、Claude Code 用户想扩展能力。不适合完全不懂编程的人（虽然 CLI 可以不用写代码，但调试还是需要一点技术）。

**不适合谁**：只想偶尔手动查个网页的人（直接自己查更快）、对 API 费用非常敏感的人、需要操作非常复杂的网页应用（比如有复杂交互的内部系统）且不想花时间调试的人。

**评分**：8.5/10 — 同类最佳之一，Rust 核心重写后性能领先，云版完善了生态。扣分的点是学习曲线和 API 成本。

## 未来趋势

- 📈 **所处阶段**：快速增长期。stars 接近 10 万，v0.13 的 Rust 核心是一个重要里程碑，说明项目在认真做性能

- ⭐ **关注度**：5/5 — 网页自动化是刚需，这个工具是目前最成熟的方案之一，必须关注。尤其是如果你有"让 AI 帮我操作网页"的需求，这个工具是解决思路的核心参考
