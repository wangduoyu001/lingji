# LiteLLM

> ⭐ 50,758 | 📅 2026-06-18 | [GitHub](https://github.com/BerriAI/litellm)
>
> 💡 **怎么标记**：改上面 `interest` 数字 → 3=必装 2=想试 1=观望 0=跳过 → 改完按 Ctrl+S 保存

## 干什么

LiteLLM 是 AI 世界的"万能遥控器"——一个统一的接口让你调用 100 多种不同的大模型，而不用管它们各自的调用方式差别多大。它的作用打个比方：就像一个万能充电头，不管你用的是 iPhone（OpenAI）、三星（Claude）、华为（Gemini）还是小米（本地模型），插上去都能充。以前开发者要在项目里用多种 AI 模型，每一种都要去读文档、写不同的代码、处理不同的返回格式；LiteLLM 把所有这些统一成了 OpenAI 的格式——你写一次代码，切换模型只需要改一个参数。它还提供 Proxy Server（网关模式），可以做费用追踪、负载均衡、速率限制、安全防护。

## 能实现什么效果

用了 LiteLLM 之后，你的 AI 应用可以做到：① 同一套代码调用 OpenAI、Claude、Gemini、Cohere、本地 Ollama、HuggingFace 等 100+ 模型；② 自动追踪每个请求花了多少钱——哪个部门用 AI 最多、哪个模型最费钱一目了然；③ 当一个模型挂了（比如 OpenAI 宕机），自动切换到备用模型（比如 Claude），用户无感知；④ 设置安全规则——阻止包含敏感信息的请求发给外部 API；⑤ 控制预算——设置每月 1000 元的 AI 调用上限，超出自动停止。

## 怎么用

- **统一 API**：在 Python 代码里 `litellm.completion(model="gpt-4", messages=...)` → 换成 Claude 只需 `model="claude-3-opus"` → 其他代码不变
- **费用监控**：部署 LiteLLM Proxy → 所有 AI 请求经过 Proxy → 后台自动生成费用报表 → 查看哪个项目花最多钱
- **容灾切换**：配置主备模型 → "用 GPT-4，如果挂了切换到 Claude" → 一个请求失败自动重试另一个
- **安全防护**：配置敏感词规则 → 用户输入包含手机号/身份证 → Proxy 自动拦截不发给外部 API
- **负载均衡**：注册多个 OpenAI API Key → Proxy 自动轮询使用 → 绕开单个 Key 的速率限制

## 运行位置

- **SDK 模式**：作为 Python 库 pip 安装，本地使用
- **Proxy 模式**：部署到自己服务器上作为网关，全公司共用
- 不需要 Docker，Python 一行命令即可启动

## 需要准备什么

- **费用**：LiteLLM 本身免费开源；但你要调用的大模型 API 需要相应付费
- **账号**：不需要 LiteLLM 账号；但需要各模型提供商的 API Key
- **API Key**：取决于你要用哪些模型——OpenAI Key、Claude Key、Gemini Key 等
- **电脑配置**：SDK 模式无所谓；Proxy 模式建议 2GB+ 内存的小服务器
- **软件依赖**：Python 3.9+

## 配合什么软件

配合任何调用 AI API 的应用使用。常用于配合 LangChain、Dify、Open WebUI 等 AI 应用作为后端网关。可以配合 Prometheus/Grafana 做监控大盘。

## 客观评价

优点：① 解决了一个真实且普遍的痛点——多模型统一调用；② Proxy 网关功能强大——费用追踪、负载均衡、安全防护一应俱全；③ 免费开源，企业友好；④ 社区活跃，5 万星。

缺点/坑：① SDK 和 Proxy 的功能差异大，文档有时混淆；② 配置 Proxy 的 YAML 文件比较繁琐，字段多容易写错；③ 部分小众模型的适配可能有问题，更新跟不上；④ 底层依赖的库多，版本冲突偶有发生。

适合谁：在多模型环境开发的 AI 工程师、需要费用管控的企业。不适合：只用一种模型的个人开发者（直接用官方 SDK 更简单）。

打分：8.5/10。实用性强到令人发指——解决了多模型管理的核心痛点。扣 1.5 分因为配置复杂度。

## 未来趋势

① 所处阶段：快速增长期——多模型趋势不可逆，LiteLLM 是受益者；② 6-12 个月：会推出可视化配置面板和更智能的自动路由；③ 关注度：4/5，多模型管理首选方案。
