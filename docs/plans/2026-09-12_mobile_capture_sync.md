# 规划：手机内容同步进灵机（视频号/抖音/小红书 → 第二大脑）

> 状态：PROPOSAL（待主人确认后实施）。原则：本地优先、零凭证、只抓公开
> 信息与主人自己的笔记，不自动下载受版权保护的视频本体。

## 1. 需求

主人在手机上刷到视频号/抖音/小红书的内容，觉得"满意 / 需要分析 / 做笔记 /
要学习 / 要实操"，希望一键同步进灵机；灵机自动整理并可在需要时调取。

## 2. 同步通道（三条，按推荐顺序）

### 通道 A：iOS 快捷指令 → 灵机捕获 API（主通道）

1. iOS「快捷指令」新建分享动作：接收【链接/文本/截图】→ 追加一行 JSON 到
   「灵机捕获」备忘（或直接 HTTP POST 到 Mac 局域网 `POST /api/capture/inbox`）。
2. 分享面板里任何 App（抖音/小红书/微信）点"分享 → 灵机捕获"即完成。
3. 保存内容 = 分享文本（含标题/链接）+ 主人随手写的一句"为什么收藏" +
   可选截图（走已有 OCR 管线）。
- 附加：剪藏 App（如 Anybox/Cubox 免费档）同样可输出到该通道。

### 通道 B：iCloud/云盘收件箱目录（离线兜底）

- 快捷指令把 JSON 落到 iCloud Drive 的 `LingJiInbox/` 目录；
- Mac 端灵机将该目录注册为只读来源（export-inbox 机制已有）， watcher 自动
  摄取、按内容哈希去重、处理后归档。
- 断网/不在同一局域网时天然可用。

### 通道 C：手动投喂中心（已有，兜底）

- 复制链接回 Mac，粘贴进「手动投喂中心」。

## 3. 同步后的处理管线（全自动）

``手机内容
  → 捕获条目（链接 + 标题 + 主人笔记 + 截图）
  → 抓取公开网页正文/封面元数据（只读公开页面，不登录、不下视频本体）
  → 截图走 OCR；正文+笔记交给本机小模型
  → 产出结构化条目：
      title / source_url / author / platform
      why_saved（主人原话）
      key_points[]（要点）
      action_type：学习 | 实操 | 分析 | 参考
      next_action（一条可执行的下一步）
  → 入记忆层（append-only）+ 自动向量化（语义可搜）
  → 分类进三个视图：
      · 记忆库·知识要点（合并进主题）
      · "稍后学习/实操"清单（按 action_type 聚合，UI 新页签）
      · Obsidian Vault：生成一篇 Clip 笔记（权威正文，可编辑）
```

## 4. 调取方式

- 手机上：快捷指令"问灵机"→ 调 `/api/observability/recall` 朗读/展示结果。
- 电脑/AI：MCP `search_memory`（见 docs/RETRIEVAL_GUIDE.md）。
- 例："我上个月收藏的讲曝光三角的那个视频要点是什么？"

## 5. 防膨胀与保留策略（同步量增长的前提）

| 数据 | 保留策略 |
| --- | --- |
| 捕获条目（含截图 OCR 文本） | 永久（权威，体积小） |
| 截图原图 | 90 天后转入冷目录；OCR 文本永久 |
| 网页正文快照 | 180 天；正文文本永久 |
| 视频本体 | 永不自动下载 |
|提炼中间产物 | 可重建，保留最近 3 轮 |
| 向量索引 | 可重建，跟随记忆层 |

通用闸门：捕获层每日增量上限（默认 200 条）防爆发；所有派生层可随时重建，
原始捕获永不删除。

## 6. 实施切片

1. P0：捕获 API + iCloud 收件箱来源 + 快捷指令配方（约 1 个任务单）。
2. P1：小模型结构化（action_type/next_action）+ Vault Clip 笔记生成。
3. P2："稍后学习/实操"UI 页签 + 手机"问灵机"快捷指令。
