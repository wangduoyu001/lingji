# 灵机桌面端快速上手

适用产品：LingJi Desktop 0.1.x

## 1. 第一次打开先做什么

进入：

```text
开始使用
→ AI 助手与记忆导入
```

点击：

```text
扫描我的 AI 软件
```

灵机会检查允许的本机位置，并把结果分成：

- 已检测到；
- 可导入；
- 需要手动导出；
- 适配器开发中；
- 未检测到。

扫描只读取目录、文件名、数量和修改时间等元数据，不读取聊天正文，不读取浏览器登录态、Token、密码或 API Key。

“检测到”不等于“已经完成永久同步”。页面会明确显示当前支持程度。

## 2. 当前支持哪些 AI 资料

| AI 工具 | 当前能力 | 操作 |
|---|---|---|
| ChatGPT | 支持官方 Export ZIP/JSON 导入 | 选择导出文件后点击“导入到灵机” |
| Codex | 支持 Codex Report 导入；已有项目与 Session 读取模型 | 选择 Report JSON 导入 |
| Claude Code | 支持安全检测；正式对话导入适配器开发中 | 当前只显示检测结果 |
| WorkBuddy | 支持安装检测；正式导出位置与适配器待确认 | 当前只显示检测结果 |

灵机不会因为发现了一个目录，就假装已经能可靠读取其中的全部历史。软件界已经有足够多的绿色假状态，不需要再添一盏。

## 3. 一键导入已有记忆

在“AI 助手与记忆导入”页面选择：

```text
ChatGPT 历史
或
Codex 工作报告
```

操作流程：

```text
选择文件
→ 导入到灵机
→ 进入统一采集队列
→ 活动记录显示进度
→ 生成人工审核候选
```

导入任务使用现有采集、去重、队列、重试和审计链路，不创建第二套导入系统。

## 4. 永久记忆如何产生

默认规则：

```text
原始资料
→ 提取与去重
→ 候选记忆
→ 人工记忆审核
→ 正式永久记忆
```

必须记住：

1. 导入整份聊天历史，不等于全部内容自动成为永久记忆。
2. AI 可以提出候选，但不能替主人批准正式记忆。
3. 只有在“人工记忆审核”中确认的候选，才进入正式长期记忆。
4. 原始资料保留来源，方便追溯和重新构建索引。
5. 当前版本不会自动把内容写入 Core Memory。

## 5. 日常使用流程

### 第一步：连接或导入

进入：

```text
开始使用
→ AI 助手与记忆导入
```

用于：

- 扫描新安装的 AI 工具；
- 导入 ChatGPT Export；
- 导入 Codex Report；
- 查看 Claude Code、WorkBuddy 的当前支持状态。

### 第二步：查看处理进度

进入：

```text
活动记录
```

查看：

- 当前任务；
- 最近完成；
- 失败任务；
- 自动重试。

普通任务会自动处理，不需要手动刷新。

### 第三步：审核候选记忆

进入：

```text
高级诊断
→ 人工记忆审核
```

逐条确认：

- 内容是否准确；
- 是否值得长期保留；
- 是否包含隐私；
- 项目和标签是否正确；
- 是否与旧记忆冲突。

### 第四步：继续投喂新资料

进入：

```text
高级诊断
→ 手动投喂中心
```

可以提交：

- 文字；
- 网页；
- 本地文件；
- 音频、视频和图片；
- ChatGPT 导出；
- Codex 工作报告。

提交前确认来源、隐私范围和当前 Workspace。

## 6. 打开后如何确认系统正常

右上角正常应显示：

```text
运行中
```

诊断信息应满足：

```text
Runtime：healthy
Runtime：managed
Workspace：你当前选择的 production 或 acceptance
DataRoot：位于你确认的非系统盘目录
```

只要 Runtime 正常，日常使用不需要逐页研究技术状态。

## 7. 高级诊断什么时候用

| 问题 | 页面 |
|---|---|
| 不知道哪个模块异常 | 脑状态 |
| 模型没有激活 | AI 与模型 |
| GPU、显存或 CPU 问题 | 系统与算力 |
| 语义检索或向量异常 | 向量中心 |
| Obsidian 没有连接 | Obsidian |
| 任务失败详情 | 任务队列明细 |
| 磁盘或数据路径问题 | 存储 |
| 升级或恢复前检查 | 备份 |
| 需要错误证据 | 日志 |
| 新版本真机验收 | 环境验收 |

没有异常时，不需要逐页研究这些技术状态。

## 8. 三个重要规则

1. 不要把 `degraded` 自动理解为整个系统崩溃。先看具体是 Runtime、Embedding、Vector、Storage 还是其他能力。
2. 不要在不知道影响时点击删除、重建、恢复或高风险设置。
3. 生产资料只在 `production` 工作空间使用；测试和验收优先使用 `acceptance`。

## 9. 出问题时怎么提供证据

在左侧底部展开“运行详情”，点击：

```text
复制诊断信息
```

只提供与问题有关的诊断和截图。

不要公开：

- API Key；
- Token；
- 私人对话正文；
- 数据库内容；
- 完整本机路径和桌面截图，除非已经脱敏。

## 10. 当前产品边界

- Desktop 是唯一正式 UI。
- Desktop 通过认证的本地 8766 API 访问后端。
- Obsidian Vault + Git 是正式知识和永久记忆正文的权威。
- SQLite 与 Qdrant 是可重建索引。
- Auto Review 只提供建议和审计，不自动执行正式记忆变更。
- Claude Code 和 WorkBuddy 当前仅完成安全检测，未宣称完整导入或自动同步。
