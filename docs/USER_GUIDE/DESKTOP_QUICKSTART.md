# 灵机桌面端快速上手

适用产品：LingJi Desktop 0.1.x

## 1. 打开后先看什么

先打开“运行状态”。

正常状态应满足：

```text
右上角：运行中
Runtime：healthy
Runtime：managed
Workspace：你当前选择的 production 或 acceptance
DataRoot：位于你确认的非系统盘目录
```

如果右上角显示“运行中”，日常使用不需要进入高级诊断。

## 2. 日常使用只走四步

### 第一步：投喂资料

进入：

```text
高级诊断
→ 手动投喂中心
```

可以提交：

- 文字；
- 网页；
- 本地文件；
- 音频、视频和图片；
- ChatGPT 导出；
- Codex 工作报告。

提交前确认：

- 来源是否正确；
- 是否允许进入记忆候选；
- 隐私范围是否合适；
- 当前 Workspace 是否正确。

### 第二步：查看处理进度

进入：

```text
活动记录
```

查看：

- 当前任务；
- 最近完成；
- 失败任务；
- 自动重试。

普通任务会自动处理，不需要手动刷新。

### 第三步：审核候选记忆

进入：

```text
高级诊断
→ 人工记忆审核
```

逐条确认：

- 内容是否准确；
- 是否值得长期保留；
- 是否包含隐私；
- 项目和标签是否正确；
- 是否与旧记忆冲突。

AI 可以提出候选，但不能替主人批准正式记忆。

### 第四步：处理异常

进入：

```text
需要我处理
```

这里只放系统不能安全自行决定的事项，例如：

- 任务失败；
- 候选记忆需要判断；
- 向量需要重建；
- 存储空间不足；
- 状态无法确认。

先读原因和影响，再执行操作。

## 3. 高级诊断什么时候用

| 问题 | 页面 |
|---|---|
| 不知道哪个模块异常 | 脑状态 |
| 模型没有激活 | AI 与模型 |
| GPU、显存或 CPU 问题 | 系统与算力 |
| 语义检索或向量异常 | 向量中心 |
| Obsidian 没有连接 | Obsidian |
| 任务失败详情 | 任务队列明细 |
| 磁盘或数据路径问题 | 存储 |
| 升级或恢复前检查 | 备份 |
| 需要错误证据 | 日志 |
| 新版本真机验收 | 环境验收 |

没有异常时，不需要逐页研究这些技术状态。

## 4. 三个重要规则

1. 不要把 `degraded` 自动理解为整个系统崩溃。先看具体是 Runtime、Embedding、Vector、Storage 还是其他能力。
2. 不要在不知道影响时点击删除、重建、恢复或高风险设置。
3. 生产资料只在 `production` 工作空间使用；测试和验收优先使用 `acceptance`。

## 5. 出问题时怎么提供证据

在左侧底部展开“运行详情”，点击：

```text
复制诊断信息
```

只提供与问题有关的诊断和截图。

不要公开：

- API Key；
- Token；
- 私人对话正文；
- 数据库内容；
- 完整本机路径和桌面截图，除非已经脱敏。

## 6. 当前产品边界

- Desktop 是唯一正式 UI。
- Desktop 通过认证的本地 8766 API 访问后端。
- Obsidian Vault + Git 是正式知识和永久记忆正文的权威。
- SQLite 与 Qdrant 是可重建索引。
- Auto Review 只提供建议和审计，不自动执行正式记忆变更。
