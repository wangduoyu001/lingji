# 灵机桌面端快速上手

适用产品：LingJi Desktop 0.1.x

## 1. 第一次打开先做什么

进入：

```text
开始使用
→ AI 助手与记忆导入
```

页面会把首次设置拆成四步：

```text
扫描
→ 连接
→ 导入
→ 审核
```

四步含义不同：

| 动作 | 作用 |
|---|---|
| 扫描 | 确认本机安装了哪些 AI、当前支持哪些能力 |
| 连接 | 让 AI 今后的任务可以调用灵机记忆 |
| 导入 | 把旧聊天、导出文件或工作报告放进灵机 |
| 审核 | 决定哪些候选值得成为正式永久记忆 |

“检测到”不等于“已连接”，“已连接”也不等于“旧历史已经导入”。

## 2. 扫描本机 AI

点击：

```text
扫描我的 AI 软件
```

灵机会检查允许的本机位置，并把结果分成：

- 已检测到；
- 可导入；
- 需要手动导出；
- 适配器开发中；
- 未检测到。

扫描只读取目录、文件名、数量和修改时间等元数据，不读取聊天正文，不读取浏览器登录态、Token、密码或 API Key。

## 3. 把灵机设置为 AI 的共享记忆

在页面中找到：

```text
让 AI 真正使用灵机记忆
```

正常情况下会看到：

```text
灵机记忆网关已运行
本机 127.0.0.1:8767
Bearer Token 认证
```

连接后的 AI 可以调用：

- 主人批准的核心记忆；
- 与当前任务相关的检索结果；
- 带来源的上下文包；
- 候选记忆提交工具。

AI 不能直接批准或覆盖 Core Memory。

### 3.1 连接 Codex

点击：

```text
Codex
→ 预览并连接
```

灵机会先显示将要修改的内容：

- 目标为 `~/.codex/config.toml`；
- 只新增或替换 LingJi 管理区块；
- 不修改模型、账号、审批或沙箱设置；
- 写入前自动备份；
- 发现同名外部配置时停止，不覆盖。

确认后点击：

```text
确认连接
```

然后：

1. 新建或重启 Codex 会话；
2. 回到灵机点击“测试连接”；
3. 状态显示“连接测试通过”后完成。

不再使用时点击：

```text
断开并回滚
```

灵机只移除自己管理的配置区块，保留其他 Codex 设置。

### 3.2 连接 Claude Code

点击：

```text
Claude Code
→ 预览并连接
```

灵机会：

- 检测官方 `claude` 命令；
- 备份现有 `~/.claude.json`（如果存在）；
- 调用官方 `claude mcp` 命令添加 user-scope MCP；
- 使用本机 HTTP 地址和 Bearer Token；
- 不直接猜测或重写 Claude 内部配置。

连接后新建 Claude Code 会话，再回到灵机点击“测试连接”。

断开时，灵机通过官方 CLI 移除 `lingji-memory`。

### 3.3 连接 WorkBuddy / CodeBuddy

当前官方提供自定义连接器或 MCP 配置页面，但没有稳定公开的个人本地配置文件供灵机安全修改。

因此灵机不会假装完成一键写入，而是：

```text
WorkBuddy / CodeBuddy
→ 复制连接配置
```

然后在 WorkBuddy / CodeBuddy 中：

```text
连接器或 MCP 设置
→ 自定义连接器 / Add MCP
→ 粘贴配置
→ 保存
→ Try to Run / 连接测试
```

配置中包含当前 Workspace 的本机 Token。不要把配置粘贴到聊天、公开文档或 Git 仓库。

### 3.4 当前 ChatGPT 边界

当前版本支持：

```text
ChatGPT 官方 Export ZIP/JSON
→ 导入灵机
```

本轮没有把本机 ChatGPT 客户端连接到 `127.0.0.1:8767`。ChatGPT 实时共享记忆需要后续受管远程连接方案，不能把本机端口直接暴露到公网。

## 4. AI 如何使用灵机记忆

连接完成后，AI 可以通过 LingJi MCP 使用：

```text
get_core_memory
search_memory
fetch_memory
build_context_pack
propose_memory
recent_changes
memory_health
```

推荐工作规则：

```text
任务开始前
→ 读取核心记忆
→ 根据任务构建相关上下文

任务完成后
→ 只把稳定决策、长期偏好、项目状态和下一步提交为候选
→ 不保存临时尝试、错误答案和重复内容
```

当前第一版本机客户端使用同一 `lingji-local` 主人记忆视图。每个 AI 的独立隐私权限和 Agent Scope 尚未完成。

## 5. 导入已有历史

在“AI 助手与记忆导入”页面选择：

```text
ChatGPT 历史
或
Codex 工作报告
```

操作流程：

```text
选择文件
→ 导入到灵机
→ 进入统一采集队列
→ 活动记录显示进度
→ 生成人工审核候选
```

当前导入能力：

| AI 工具 | 当前能力 | 操作 |
|---|---|---|
| ChatGPT | 支持官方 Export ZIP/JSON | 选择导出文件后点击“导入到灵机” |
| Codex | 支持 Codex Report JSON | 选择 Report 后导入 |
| Claude Code | 对话导入 Adapter 待开发 | 当前只支持实时 MCP 连接 |
| WorkBuddy / CodeBuddy | 对话导入 Adapter 待开发 | 当前只支持自定义连接配置 |

导入任务使用现有采集、去重、队列、重试和审计链路，不创建第二套导入系统。

## 6. 永久记忆如何产生

默认规则：

```text
原始资料或 AI 候选
→ 提取与去重
→ 候选记忆
→ 人工记忆审核
→ 正式永久记忆
```

必须记住：

1. 导入整份聊天历史，不等于全部内容自动成为永久记忆。
2. AI 可以提出候选，但不能替主人批准正式记忆。
3. 只有在“人工记忆审核”中确认的候选，才进入正式长期记忆。
4. 原始资料保留来源，方便追溯和重新构建索引。
5. 当前版本不会自动把内容写入 Core Memory。

## 7. 日常使用流程

### 第一步：确认连接

进入：

```text
开始使用
→ AI 助手与记忆导入
```

查看常用 AI 是否显示：

```text
连接测试通过
```

### 第二步：让 AI 正常工作

在 Codex、Claude Code 或 WorkBuddy 中提出任务。AI 可按任务需要调用 LingJi 工具。

### 第三步：查看处理进度

进入：

```text
活动记录
```

查看导入或候选处理任务是否完成、失败或重试。

### 第四步：审核候选记忆

进入：

```text
高级诊断
→ 人工记忆审核
```

逐条确认：

- 内容是否准确；
- 是否值得长期保留；
- 是否包含隐私；
- 项目和标签是否正确；
- 是否与旧记忆冲突。

### 第五步：继续投喂新资料

进入：

```text
高级诊断
→ 手动投喂中心
```

可以提交文字、网页、文件、媒体、ChatGPT 导出和 Codex 工作报告。

## 8. 打开后如何确认系统正常

右上角正常应显示：

```text
运行中
```

诊断信息应满足：

```text
Runtime：healthy
Runtime：managed
Workspace：你当前选择的 production 或 acceptance
DataRoot：位于你确认的非系统盘目录
```

AI 连接页还应显示：

```text
灵机记忆网关已运行
127.0.0.1:8767
```

只要 Runtime 和记忆网关正常，日常使用不需要逐页研究技术状态。

## 9. 高级诊断什么时候用

| 问题 | 页面 |
|---|---|
| 不知道哪个模块异常 | 脑状态 |
| 模型没有激活 | AI 与模型 |
| GPU、显存或 CPU 问题 | 系统与算力 |
| 语义检索或向量异常 | 向量中心 |
| Obsidian 没有连接 | Obsidian |
| 任务失败详情 | 任务队列明细 |
| 磁盘或数据路径问题 | 存储 |
| 升级或恢复前检查 | 备份 |
| 需要错误证据 | 日志 |
| 新版本真机验收 | 环境验收 |

## 10. 安全规则

1. 不要把 `degraded` 自动理解为整个系统崩溃，先看具体能力。
2. 不要在不知道影响时点击删除、重建、恢复或高风险设置。
3. 生产资料只在 `production` 使用，测试优先使用 `acceptance`。
4. 不要公开 LingJi MCP Token、连接配置或完整本机路径。
5. 不要把本机 8766 或 8767 端口映射到公网。
6. 写入第三方 AI 配置前先阅读预览和备份说明。

## 11. 出问题时怎么提供证据

在左侧底部展开“运行详情”，点击：

```text
复制诊断信息
```

只提供与问题有关的诊断和截图。

不要公开：

- API Key；
- Control Token 或 MCP Token；
- 私人对话正文；
- 数据库内容；
- 含 Authorization Header 的连接配置；
- 完整本机路径和桌面截图，除非已经脱敏。

## 12. 当前产品边界

- Desktop 是唯一正式 UI。
- Desktop 通过认证的本地 8766 API 管理后端。
- 本机 AI 通过认证的 8767 MCP 使用记忆。
- Obsidian Vault + Git 是正式知识和永久记忆正文的权威。
- SQLite 与 Qdrant 是可重建索引。
- Auto Review 只提供建议和审计，不自动执行正式记忆变更。
- Claude Code 与 WorkBuddy 历史导入尚未完成。
- 每个 AI 的独立权限和 Agent Scope 尚未完成。
- ChatGPT 实时连接和跨设备远程访问尚未完成。
