# 灵机独立本地控制中心架构

## 1. 核心定位

灵机的主 UI 是单独启动的本地桌面控制中心，不是 Obsidian 插件。

```text
LingJi Local Control Center
        ↓ localhost API / WebSocket
LingJi Python Runtime
        ↓
SQLite + Obsidian Vault + Raw Storage + Memory Index
```

Obsidian 的职责是长期知识阅读、人工编辑、关系浏览和最终知识权威。Obsidian 插件只能作为可选的快捷采集入口与深度链接，不承担完整系统管理。

## 2. 推荐技术方案

### 桌面壳

优先采用 Tauri 2：

- 免费、开源。
- 支持 Windows，并可扩展到 macOS、Linux。
- 可以使用 React、Vue、Svelte 等前端。
- 不需要为每个应用打包完整浏览器引擎。
- 可调用本地 Sidecar 或 localhost 服务。

### 前端

建议 React + TypeScript + Vite：

- 组件生态成熟。
- 数据表格、关系图、日志流和参数表单容易维护。
- 与后端协议分离，未来可同时提供浏览器本地访问模式。

### 后端

复用现有 Python 服务，并增加 FastAPI 控制层：

- REST API：查询、修改配置、创建任务、审核内容。
- WebSocket：实时任务进度、日志、服务状态和错误通知。
- MCP、CLI、桌面 UI 共用同一个 Service Layer，禁止各写一套业务逻辑。

### 数据层

- `storage/lingji_state.db`：任务、状态、设置、审计和 UI 操作记录。
- `storage/lingji_memory.db`：可重建召回索引。
- Obsidian Vault：正式知识正文和人工编辑权威。
- `storage/raw/`：原始来源快照。

UI 不允许直接操作 SQLite 表或任意覆盖 Vault 文件，必须通过本地 API 和既有服务层执行。

## 4. 关键页面

### 4.1 总览

- 服务运行状态。
- 当前模式：NORMAL、DEGRADED、SAFE_MODE。
- 待处理任务、失败任务、等待审核数量。
- 最近采集、最近写回、最近错误。
- CPU、内存、磁盘、模型和索引状态。
- 快速按钮：扫描、暂停、恢复、安全模式、重建索引。

### 4.2 采集中心

- 粘贴网址、文本或文件。
- 选择来源：网页、公众号、视频号、抖音、小红书、ChatGPT、Codex、GitHub、微信、本地文件、视频、音频。
- 选择项目和隐私等级。
- 显示当前能获取的字段与缺失项。
- 预览入库结果后提交。

### 4.3 任务队列

- queued、running、retrying、failed、completed。
- 进度、Worker、租约、尝试次数、下一次重试时间。
- 暂停、继续、重试、取消和查看错误。
- 危险操作需要确认。

### 4.4 数据与参数

- 查看所有 Adapter、Provider、模型、路径、限额和开关。
- 参数按模块分组，不直接展示无解释的环境变量墙。
- 显示默认值、当前值、来源、修改时间和是否需要重启。
- 支持导出和恢复配置。

### 4.5 Skill 中心

- Skill 清单、版本、来源、能力、依赖和兼容 Agent。
- 启用、禁用、验证、更新和关联项目。
- Obsidian 继续保存人类可读清单，但主要管理操作在本地 UI 完成。

### 4.6 Obsidian 与文件

- 打开对应 Obsidian 笔记。
- 查看文件结构、索引状态、孤立文件和冲突。
- 允许人工整理建议，但批量移动前必须预览和备份。

### 4.7 存储生命周期与冷存储

保留时间、硬盘空间阈值、冷存储位置和自动清理策略不得写死在代码中，必须在独立本地 UI 中由主人自定义。

UI 至少提供：

- 原始资料、正式知识、历史版本、派生媒体、缓存、日志和临时文件的分类占用。
- 各类别保留天数、最大容量、最大版本数和自动清理开关。
- 磁盘剩余空间预警阈值、灵机最大占用上限和增长趋势。
- 冷存储启用开关、目标目录、迁移条件、保留策略和恢复入口。
- 清理前预览、预计释放空间、受影响文件清单和排除规则。
- 手动立即执行、定时执行、暂停执行和恢复默认值。
- 配置导入、导出、版本记录和修改审计。

安全约束：

- 原始资料和正式知识默认不得自动删除。
- 任何自动清理只能处理明确标记为可重建、可归档或可过期的数据。
- 冷存储迁移和删除前必须校验目标文件完整性。
- 删除动作优先进入可恢复区域，不直接永久删除。
- 清理、迁移、恢复失败不得影响主服务和知识检索。
- 所有默认值只是初始建议，最终以 UI 中保存的用户配置为准。

## 5. Obsidian 插件的正确地位

保留插件时，只允许承担：

- 从 Obsidian 打开本地控制中心。
- 将当前笔记或选中文字提交到采集队列。
- 打开关联来源、项目或任务。
- 显示简要服务状态。

插件不得承担：

- 完整参数管理。
- 完整任务队列管理。
- 系统日志管理。
- 模型和 Provider 配置。
- 备份恢复。
- 全局数据看板。

插件可以被完全关闭，灵机核心功能仍必须正常工作。

## 6. 启动方式

最终目标：

```powershell
LingJi.exe
```

启动流程：

```text
检查 Python Runtime / 打包 Sidecar
检查配置与数据库
启动本地后端
绑定 127.0.0.1 随机或固定端口
启动桌面窗口
显示健康状态
```

开发阶段可使用：

```powershell
python run_service.py
npm run tauri dev
```

## 7. 安全边界

- 默认只绑定 `127.0.0.1`。
- UI 会话使用本机随机令牌。
- 不允许网页内容调用本地危险接口。
- 删除、发布、付款、账号和私密导出需要二次确认。
- UI 只通过白名单 API 调用服务。
- 所有修改写入审计日志。

## 8. 开发顺序

1. 先抽出稳定的 Local Control API。
2. 建立 Tauri + React 基础壳和总览页。
3. 接入任务队列、状态、日志和配置。
4. 接入采集中心、Skill 中心和项目中心。
5. 接入数据浏览、关系图谱和媒体处理。
6. 接入存储统计、时间策略、硬盘阈值和冷存储配置。
7. 最后再保留或精简 Obsidian 插件快捷入口。

## 9. 验收标准

- 不打开 Obsidian 也能启动、查看和管理灵机。
- 不安装 Obsidian 插件也不影响采集、队列、模型、日志和设置。
- UI 与 MCP、CLI 调用相同后端服务。
- 重启后任务、参数和状态可恢复。
- 时间、硬盘空间和冷存储策略可在 UI 中修改并持久化。
- 所有危险操作有确认、备份和审计。
