# LingJi 真实数据试运行与记忆质量验收

> 本文件定义灵机进入真实数据试运行时的统一验收方法。
>
> 它不替代 `CODEX_ACCEPTANCE_INSTRUCTIONS.md` 的安全基线，也不允许绕过产品 Commit、Artifact、Production / Acceptance 隔离和主人观察要求。
>
> 执行顺序固定为：先通过 Day 0 安全门槛，再进入小批量真实数据试运行。Day 0 未通过时禁止导入主人真实资料。

## 1. 目标

用真实使用证明灵机能够：

- 安全保存和检索主人授权的数据；
- 保留原文、来源和导入链路；
- 不把剧本、公开资料或第三方内容误写成主人个人记忆；
- 不把候选记忆自动批准为永久记忆；
- 在 Codex 新会话中通过 LingJi MCP 正确取回必要上下文；
- 在覆盖安装、Core 重启和 Windows 重启后保持数据和连接；
- 通过可重复评分暴露召回、来源、去重和记忆边界问题。

## 2. 执行职责

### Codex 负责

- 开始前清理；
- 安装、启动和自动验证；
- 进程、端口、API、MCP 和配置检查；
- 准备和导入经主人授权的数据；
- 构造质量问题集；
- 记录答案、来源和评分证据；
- 执行重启、重复导入和故障路径；
- 生成报告、提交 GitHub、远程复读和结束清理。

### 主人负责

仅在固定检查点提供人类结论：

- 是否出现 PowerShell、CMD 或黑窗；
- 第一次打开是否知道下一步；
- 页面和状态文案是否能看懂；
- 真实 Codex 客户端是否能看到并调用 LingJi 工具；
- 亲自批准一个测试候选、拒绝一个测试候选；
- Windows 重启后界面是否恢复；
- 对已知答案的问题判断结果是否正确。

Codex不得代替主人填写肉眼或主观结论。

## 3. 数据安全边界

### 允许

- 主人明确授权的短剧剧本、项目资料、ChatGPT 导出、Codex 报告和 Obsidian 目录；
- 为验收专门制作的无隐私 fixture；
- Acceptance Workspace 中带本轮前缀的测试候选和测试数据；
- Production 的只读查询和身份核验。

### 禁止

- 未经授权扫描整盘、整个用户目录或浏览器数据；
- 把主人正式 Production 数据复制到临时公开证据；
- 把剧本人物、剧情和台词当作主人个人事实；
- 把公开资料或第三方观点静默写入 Core Memory；
- 在 Production 写入本轮测试候选、fixture 或质量题；
- 提交真实聊天、数据库正文、Token、Authorization、完整绝对路径或未脱敏截图。

## 4. Day 0 安全门槛

Day 0 必须在任何真实数据导入前完成。

### 4.1 身份与安装

- 精确产品 Commit、Artifact ID、ZIP、安装器、Desktop、Sidecar、Manifest 和哈希一致；
- 使用固定安装器直接覆盖安装；
- 不卸载，不删除主人 DataRoot、Vault、正式记忆或 AI 客户端配置；
- DataRoot 不迁回 C 盘；
- 安装、启动和重启过程由主人确认无黑窗。

### 4.2 Runtime 与端口

- Desktop、受管 Core 和预期 MCP 子进程数量正确；
- 无重复 Core、无孤儿 MCP；
- 8766 和 8767 只监听 `127.0.0.1`；
- Runtime 为 healthy / managed；
- 无 Token 和错误 Token 被拒绝；
- 正确 Token 可以使用。

### 4.3 数据和记忆边界

- Production 与 Acceptance 的 DataRoot、Vault、数据库、Qdrant、日志、设置和 Token 物理隔离；
- `propose_memory` 只生成候选；
- 未批准前 Core Memory 数量不增加；
- 拒绝候选后不进入正式记忆；
- 主人批准后仅目标候选进入正式记忆；
- A-01 回归通过，显式空环境不得读取或修改主人真实 `CODEX_HOME`；
- 连接器备份、回滚和恢复不破坏主人其他设置。

### 4.4 真实 Codex 调用

必须在新 Codex 会话中真实调用：

```text
get_core_memory
search_memory
build_context_pack
memory_health
propose_memory
```

HTTP 脚本调用不能替代真实客户端调用。

### 4.5 生命周期

- 连续三轮 Core 重启后 Runtime、端口、MCP、Workspace、DataRoot 和 Vault 恢复；
- 一次 Windows 重启后恢复；
- Windows 重启后再做一轮 Core 重启；
- 主人确认窗口和界面行为正常。

### 4.6 Day 0 判定

以下任一情况发生，Day 0 为 `FAIL`，禁止进入真实数据试运行：

- Production 被测试写入或污染；
- 数据丢失或覆盖安装破坏数据；
- 自动批准永久记忆；
- Token、私人内容或用户配置泄露；
- A-01 隔离回归失败；
- Runtime、端口、MCP 或真实 Codex 调用不可用；
- 重启后数据或服务无法恢复；
- 强制自动测试失败；
- 主人必需观察项失败。

环境、Artifact、客户端或主人观察暂时无法完成时为 `BLOCKED`，不得伪造 PASS。

## 5. Stage 1 小批量真实数据

Day 0 PASS 后，先导入最小真实样本：

```text
1 部主人授权的短剧剧本
1 份 Codex 开发报告
少量主人授权的 ChatGPT 历史
Obsidian 中 1 个明确授权目录
```

每一类数据必须记录：

- source type；
- source name 的脱敏标识；
- adapter version；
- source hash；
- input hash；
- idempotency key；
- raw snapshot 是否存在；
- provenance 是否完整；
- 导入开始和结束时间；
- 成功、失败、重复和候选数量。

### Stage 1 必测

- 原文能够追溯；
- 来源正确；
- 重复导入不重复生成正式内容；
- 无效文件失败且不产生脏正式记忆；
- 导入只生成候选，不自动写 Core Memory；
- 剧本内容没有进入主人个人事实；
- Codex 新会话可以检索并引用正确来源；
- 删除本轮测试候选不影响主人其他数据。

Stage 1 有 P0/P1 问题时立即停止扩容。

## 6. Stage 2 扩展真实数据试运行

Stage 1 通过后，可逐步扩展到：

```text
最多 10 部主人授权的短剧剧本
1 个真实短剧项目资料集
更多主人授权的 ChatGPT 历史
Codex 开发报告
现有 Obsidian 授权目录
```

不得一次性全量导入。每次扩容前必须记录当前数量和磁盘占用，扩容后检查：

- raw、候选、正式记忆和索引数量变化可解释；
- 没有异常倍增；
- 没有来源丢失；
- 没有 Production / Acceptance 串用；
- 重启后数量保持；
- 重复导入保持幂等。

## 7. 记忆质量问题集

Codex 必须为每类真实资料建立主人可验证的问题集。问题必须覆盖：

### 7.1 精确事实

例如：

- 某剧本第 1 集的主要钩子是什么；
- 某角色第一次身份反转发生在哪里；
- 某项灵机架构决定在哪份报告中确定。

### 7.2 跨文档比较

例如：

- 哪几部剧本使用相似开场冲突；
- 两份开发报告对同一模块的决定有什么变化；
- 哪些资料同时提到同一人物、功能或风险。

### 7.3 来源核验

每个答案必须返回：

- 来源类型；
- 来源标识；
- 可定位片段或文档位置；
- 匹配理由；
- 无法确定时明确说明未知。

### 7.4 负面和边界问题

必须故意询问资料中不存在的内容，验证系统：

- 不编造；
- 不拿相似剧本冒充；
- 不把第三方资料当主人个人经历；
- 不跨 Workspace 泄露；
- 不把候选记忆当已批准记忆。

## 8. 评分规则

每个问题按下列标准评分：

```text
2 分：答案正确，来源正确，边界正确
1 分：主体正确，但细节、来源定位或表达存在问题
0 分：错误、找不到、张冠李戴、来源错误或越权
```

每批至少 20 题，其中：

```text
精确事实 ≥ 8
跨文档比较 ≥ 4
来源核验 ≥ 4
负面和边界问题 ≥ 4
```

计算：

```text
quality_score = 实得分 / 满分 × 100%
source_accuracy = 来源正确题数 / 有来源要求题数 × 100%
false_positive_rate = 不存在却被错误回答的题数 / 负面题数 × 100%
```

## 9. 通过标准

### 安全指标，必须全部满足

```text
正式数据丢失：0
Production 污染：0
自动写入永久记忆：0
Token 或隐私泄露：0
主人配置破坏：0
覆盖安装破坏数据：0
```

### 功能和质量指标

```text
Day 0：PASS
Stage 1：PASS
Codex MCP 真实调用成功率：≥ 95%
关键资料 quality_score：≥ 90%
source_accuracy：≥ 95%
false_positive_rate：≤ 5%
重复导入产生重复正式内容：0
人工审核链成功率：100%
Windows 重启后恢复：100%
```

质量分数未达标但不存在 P0/P1 安全问题时，最终结论可以是 `FAIL`，报告必须列出具体召回、来源、切分、排序或边界缺陷，不得用“基本可用”掩盖。

## 10. 主人检查点

Codex 只在以下节点请求主人观察：

### Checkpoint A：安装与首次打开

主人回答：

```text
黑窗：有 / 无
首页：正常 / 异常
下一步：知道 / 不知道
状态文案：能区分 / 不能区分
```

### Checkpoint B：Codex 真实连接

主人回答：

```text
LingJi 工具：可见 / 不可见
真实调用：成功 / 失败
返回内容：正确 / 错误
```

### Checkpoint C：记忆审核

主人亲自批准一个测试候选、拒绝一个测试候选，然后回答：

```text
批准：成功 / 失败
拒绝：成功 / 失败
页面：能看懂 / 不能看懂
```

### Checkpoint D：Windows 重启后

主人回答：

```text
黑窗：有 / 无
灵机恢复：正常 / 异常
页面操作：正常 / 异常
```

### Checkpoint E：质量题抽查

主人至少抽查 10 题，确认答案和来源评分。Codex不得自己替主人判定全部真实内容是否正确。

## 11. 报告要求

最终报告除 `REPORT_TEMPLATE.md` 通用字段外，必须包含：

- Day 0 每项结果；
- Stage 1 和 Stage 2 导入清单与数量；
- 问题集分类和题数；
- quality_score、source_accuracy、false_positive_rate；
- 主人五个检查点结论；
- 重复导入、失败路径和重启结果；
- 候选批准/拒绝前后的数量变化；
- Production / Acceptance 隔离证据；
- 未覆盖数据源和客户端；
- P0/P1/P2 缺陷；
- 清理前后状态；
- 报告 Commit、远程复读和 PR 评论。

公开报告不得包含真实剧本正文、私人聊天、Vault 正文、数据库内容、Token、完整路径或未脱敏截图。

## 12. 清理

### 开始前

- 删除上一轮任务的临时根目录；
- 删除重复 Artifact、安装包、解压目录、普通成功日志、截图、fixture、checkpoint、临时配置副本和 worktree；
- 关闭 LingJi 残留进程；
- 释放 8766 / 8767；
- 确认没有孤儿 MCP。

### 完成后

- 删除本轮 Artifact、重复安装包和解压内容；
- 删除普通成功日志、截图、fixture 和 checkpoint；
- 删除临时配置副本和 worktree；
- 删除带本轮前缀的 Acceptance 测试候选和测试资料；
- 真实授权资料是否保留由任务单明确，不得自行删除；
- 不删除 Production DataRoot、主人正式 Acceptance 数据、Vault、正式记忆和用户 AI 配置；
- 报告远程复读后更新结果回执，再次 push 和远程复读；
- 最终删除任务临时根目录。

## 13. 最终判定

```text
PASS
= Day 0、Stage 1、质量指标、主人检查点、远程提交和清理全部通过

FAIL
= 已执行的强制安全、功能或质量项失败

BLOCKED
= 环境、Artifact、客户端、主人观察或远程提交导致关键项无法完成
```

不得把 `NOT_TESTED`、`PENDING` 或关键 `SKIPPED` 汇总成 PASS。
